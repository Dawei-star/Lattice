# AI 文件管理工作台设计

## 目标

在现有 Lattice 笔记、目录和 Vault 边界内增加一个 AI 命令面板。用户可以用自然语言搜索、整理、重命名、创建、编辑、复制、移动或删除文件；模型只负责理解意图和生成结构化计划，实际文件写操作统一经过安全操作服务并要求确认。

## 架构

- Web：`AIAssistantPanel` 负责聊天、Markdown/代码片段、配置、操作预览和审计历史。
- Server：`/api/ai` 提供聊天、操作预览、操作执行和审计历史。没有外部模型配置时使用本地规则助手；配置了 OpenAI-compatible endpoint 时由服务端代理请求，API key 只在请求内存中使用，不写日志或磁盘。
- 操作服务：限制在 Vault 根目录内，支持 `read/create/update/delete/move/copy`，拒绝路径穿越，写操作统一记录 actor、来源、结果和目标路径。
- CLI：`npm run ai -- <chat|preview|execute|history>` 调用同一套 HTTP API，因此聊天和终端拥有相同的权限边界与审计格式。

## 数据流

1. 用户输入消息，面板提交当前文件和目录摘要作为上下文。
2. AI 返回 `reply`、`suggestions`、`references` 和可执行 `actions`。
3. 面板调用 preview 获得存在性、风险和目标摘要，展示确认按钮。
4. 用户确认后 execute 执行动作并刷新侧栏/笔记索引；成功或失败写入审计日志。

## 权限与错误处理

- 读取类动作可直接预览；创建、更新、移动、复制和删除必须带显式确认。
- 所有路径使用 Vault 相对路径规范化，禁止绝对路径、`..` 和越界符号。
- 外部 AI 失败时保留用户消息和本地助手 fallback；外部 API key 不进入历史记录。
- 执行失败按动作返回结果，已完成动作不回滚，界面明确显示部分成功状态。

## 验证

- Server 单元测试覆盖本地助手、路径安全、preview/execute 和审计记录。
- Web 回归测试覆盖打开 AI 面板、发送消息、预览并确认操作。
- 构建、现有主题测试和 CLI help 作为交付门禁。
