## 0. 总体判断

**单文件的工程质量明显高于同规模项目平均水平**:分层纪律严格、迁移器带 sha256 漂移检测、错误契约完整、SQL 全面参数化、运行时依赖只有 3 个、注释普遍解释「为什么」。这些都应该保持。

但有三类问题需要**立即/优先**处理:

| # | 类别 | 一句话结论 |
|---|------|-----------|
| 1 | **仓库管理事故** | 桌面端源码(`desktop/`)、全部文档(`docs/`)、AI 模块(`server/src/modules/ai/`)、`scripts/` 均未纳入版本控制;`scripts/smoke.mjs` 已丢失导致 `npm run test:api` / `verify` 直接报错 |
| 2 | **两个真实可利用的安全漏洞** | 自研消毒器「未知标签解包」存在子树逃逸(存储型 XSS);Electron `isInternalUrl` 用 `startsWith` 判定,可被 `@` userinfo 语法绕过,远程页面可拿走 preload 暴露的全部文件读写 IPC |
| 3 | **核心架构的性能与数据风险** | 「Markdown 为真源 + SQLite 为投影 + 任意文件变更全量重建」的设计,让每次自动保存都变成 O(全库) 的同步事务;同名笔记会写同一个文件互相覆盖,存在静默丢数据路径 |

### 2.2 安全漏洞(改动都很小)

**S-1 消毒器子树逃逸(存储型 XSS)** — `web/src/lib/sanitize.js:75-79`
未知标签走 `replaceWith(...element.childNodes)` 后直接 `return`,被提升的子节点不再被清洗;外层循环遍历的是替换前的快照,永远访问不到新节点。构造 `<font><img src=x onerror=...></font>` 即可让任意属性/事件处理器进入 `innerHTML`。marked 默认放行原始 HTML,这层消毒是唯一防线。

修复(解包前先递归清洗):
```js
if (!ALLOWED_TAGS.has(tag)) {
  for (const child of [...element.children]) cleanElement(child);
  element.replaceWith(...element.childNodes);
  return;
}
```
补一组 `<section>/<font>/<article>` 包裹 `onerror`/`javascript:` 的回归测试;中期考虑换 DOMPurify。

**S-2 Electron 内部 URL 判定绕过** — `desktop/src/main.js:390-392`
`targetUrl.startsWith(appUrl)` 可被 `http://127.0.0.1:5188@evil.com/`(userinfo 语法)绕过:远程页面在应用窗口内加载并拿到 `window.latticeDesktop` 的 10 个 IPC 方法(readMarkdownFile / writeMarkdownFile / removeMarkdownFile…),可整库外传或删库。恶意笔记里放一条这样的链接即触发。

修复:按 origin 精确比较
```js
function isInternalUrl(targetUrl, appUrl) {
  try { return new URL(targetUrl).origin === new URL(appUrl).origin; } catch { return false; }
}
```
配套:`shell.openExternal` 增加协议白名单(仅 https/http,当前 `file:`、任意 scheme 都会被调起,`main.js:374,379`);`setWindowOpenHandler` 一律 deny 后走系统浏览器。

### 2.3 数据安全(静默丢数据路径)

**同名笔记互相覆盖** — `notes.service.js:56-59` 以「目录/安全化标题.md」为文件路径,schema 不限制同名笔记 → 两篇同名笔记写同一文件,后写覆盖先写;下一次 watcher 重建后,被覆盖那篇连同正文从数据库里消失。
**双写非原子** — `notes.service.js:163-186` 先提交 DB 事务再写文件,写文件失败(磁盘满/杀软锁 EPERM)时 DB 已是新值、文件是旧值且无补偿;反向(create 先写 DB 后写文件失败)则文件事件触发重建时把这篇笔记从 DB 抹掉。

修复方向(二选一,推荐前者):
1. **文件为唯一真源**:写入路径改为「写文件成功 → 再 upsert 投影」;文件名引入 id 前缀(`id-标题.md`)或 `notes` 表增加稳定 `file_path` 列 + 唯一约束,杜绝同名覆盖。
2. 写文件失败时回滚/标记 dirty 并进入重试队列。

## 3. P1 — 性能重构(2–4 周)

### 3.1 后端:watcher/indexer 增量化(当前最大性能炸弹)

现状链路:任意文件事件(`watcher.js:36-41`,180ms 防抖)→ `adapter.scan()` 递归串行读全部 .md → `rebuildProjection`(`indexer.js:13-16`)在**一个同步事务里** `DELETE FROM notes/folders/tags/notes_fts` 再逐条重插、逐篇 `syncForNote` + `rebuildForNote`。node:sqlite 是同步 API,几千篇笔记时每次自动保存 = 秒级事件循环阻塞,所有请求排队。启动时(`server/src/index.js:47-58`)同样全量重建一次。

分三步:
1. **增量**:watcher 拿到 filename 后只对该文件 `readFile → upsert`;单笔记的 `syncForNote`/`rebuildForNote` 本来就是现成的;`filename === null`(Windows 会发生,当前直接丢弃)也要调度。
2. **跳过未变**:notes 表加 `content_hash` 列,投影重建时 hash 相同直接跳过。
3. **稳定 ID**:`folders` 以 path 为自然键 `INSERT OR IGNORE` 后按 path 查回既有 id;`tags` 不再 `DELETE FROM tags`(现有 `findIdsByNames` 复用逻辑被这句 DELETE 架空),重建后统一 `pruneOrphans`。当前每次重建 folders/tags 都生成新 UUID,前端持有的 `folderId`/`tagId` 在任意外部编辑或目录改名后大面积失效。

### 3.2 后端:索引与查询

- `findByTitle`(`notes.repository.js:48-53`)`SELECT * WHERE title COLLATE NOCASE = ?` 无索引支撑且拉全文,被 `rebuildForNote` 逐链接调用 → O(链接数 × 全表 × 正文字节)。加 `ix_notes_title (title COLLATE NOCASE)`,resolve 只取 `id`,重建场景预载 `Map<title, id>` 一次解析。
- 列表接口(`list`,`notes.repository.js:106-109`)拉整篇 content 只为算 140 字摘要 → 改 `substr(content,1,300)` 或持久化 excerpt 列。
- 图谱 `countsForNotes` 用 IN(全部 id)(`links.repository.js:101-126`),超过 SQLite 32766 变量上限直接报错 → 临时表 join 或分批;图谱结果按 `max(updated_at)` 做内存缓存。
- `claimsDanglingLinks` 的 `target_title COLLATE NOCASE` 同样需要索引。

### 3.3 前端:渲染与交互热点

- **Markdown 管线不识别代码围栏**(正确性 + 性能,`lib/markdown.js:51-80`):token 化/回填不区分 ``` 围栏,代码块里写 `[[标题]]` 会被替换成真实链接/嵌入卡片——双链笔记的高频文档场景。加围栏状态机。
- **分栏预览每键全文重渲染**(`MarkdownPreview.jsx:25-28`):`useMemo([content])` 每按键触发 marked 全文解析 + DOMParser 全树消毒 + innerHTML 整体重建,万字笔记每键 50–150ms。对传入预览的 content 加 150–250ms 防抖(`useDebouncedValue` 现成);进一步按段落 hash 分段缓存。
- **请求竞态无保护**(`useVault.js:229-260`):`openNote`/`refreshNotes` 无 AbortController/序号检查,快速切换笔记时旧响应覆盖新数据(搜索是唯一有 cancelled 保护的)。统一加序号或 signal。
- **列表 60 条硬上限**(`useVault.js:17`):后端契约支持分页但前端从未传 offset,第 61 篇起永远不可见 → 触底加载更多。
- **保存管线固定 sleep + 全量刷新**(`useVault.js:339-340`):每次自动保存 `sleep 260ms` 后并发 6 个刷新请求(含全量 noteIndex)→ 节流合并 + 用后端写回的 updatedAt 替代固定等待;`saveNote` 串行化(白板的 saveQueue 已是现成范式)。
- **图谱**(`GraphView.jsx:101`、`forceGraph.js:59-84`):每帧 `getComputedStyle` 是固定税,移出帧循环缓存;>1–2k 节点需网格分桶或 Barnes-Hut;现有「alpha 收敛停帧、DPR 适配、指针锚点缩放」保持。
- **白板**(`CanvasView.jsx:107-119,579-580`):拖拽每 pointermove 触发全树重渲染 + 每条边两次 `nodes.find` → rAF 合并 setState、卡片 React.memo、`Map<id,node>` 索引、save effect 加 500ms 防抖(保留现有 revision 机制);删除只读不写的 localStorage 死代码(`:742-748`)。

### 3.4 同步 I/O 收敛

canvas / ai 模块全用 `readFileSync/writeFileSync/rmSync`(如 `canvas.service.js:19-48`、`ai.service.js:152-224`),vault 侧已有 async 范式,统一迁到 `node:fs/promises`;`writeSync` 保留但注明取舍。
